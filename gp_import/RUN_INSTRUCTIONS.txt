GP -> CLARITY : ONE-SHOT RUN
============================================================

WHAT THIS DOES, IN ONE GO
  1. imports the old Great Plains sales history into primary.accdb
  2. copies those same rows into secondary.accdb so the two match
  3. audits both and writes GP_Verify_Report.txt

You run ONE file. It backs every database up before writing, only ever ADDS
records, and is safe to run again - anything already done is skipped.

BEFORE YOU START
----------------
1. Close Clarity and Access on this PC.

2. Put these files in ONE folder, e.g. C:\Users\bwilde\Desktop\GP

3. Copy the store databases into that folder, either way:

   ALL THREE STORES AT ONCE - keep the store folders:
       GP\1ORM\primary.accdb   GP\1ORM\secondary.accdb
       GP\2SDY\primary.accdb   GP\2SDY\secondary.accdb
       GP\3MRY\primary.accdb   GP\3MRY\secondary.accdb

   ONE STORE AT A TIME - files sit directly in GP\:
       GP\primary.accdb        GP\secondary.accdb
     and name the store when you run it (see below).

   Copy BOTH primary and secondary for every store you bring down.


RUN IT
------
Double-click the one that matches your Office:

    RUN_ALL_32bit.bat     32-bit Office  (most common)
    RUN_ALL_64bit.bat     64-bit Office

Doing one store at a time? Open a command prompt in the folder and run:

    RUN_ALL_32bit.bat -Store 1ORM          (or 2SDY, or 3MRY)

It lists the databases it found, tells you what it will do, and waits.
Type  GO  and press Enter.

Healthy progress looks like:
    Verified: all database files are free.
    Mapping which database holds which table...
    Backup 1ORM|primary -> ...
    Preloading lookup caches...
    STAGE 1: notes + customers
    ...customer and slip counters ticking up...
    ################  STAGE 2 : copy into secondary
    ################  STAGE 3 : audit

Leave it until it prints  === RUN ALL COMPLETE ===


WHEN IT FINISHES
----------------
1. OPEN GP_Verify_Report.txt AND READ THE SUMMARY AT THE BOTTOM.
   "No problems found."  -> you are good.
   Anything under PROBLEMS -> do NOT put the files back; send me the report.

2. Spot-check in Clarity: find an old customer, confirm their 2000-2005
   history is there and the amounts look right.

3. Copy primary.accdb and secondary.accdb back up to the server.
   Do NOT copy back any file named *backup_*.accdb - those are the safety
   copies. Leave them here until you are happy.

4. Send me GP_Verify_Report.txt.


KEEP THIS FILE
--------------
    gp_assigned_ids.csv

It records the customer ID given to each GP customer. It is what makes the
second and third store agree with the first. Do not delete it until all
three stores are done.


OPTIONS
-------
  -Store 1ORM        which store, when the files sit directly in the folder
  -SkipSecondary     stages 1 and 3 only; secondary is not touched
  -WhatIfSecondary   stage 2 only reports what it would copy, writes nothing
  -Auto              no prompts at all (for a scheduled run)

There is also a read-only helper you can run any time, even mid-import:
    Run_Check_Secondary.bat    compares primary, secondary and the backup


IF SOMETHING GOES WRONG
-----------------------
Nothing is changed before the databases are backed up, and each stage stops
the run rather than continuing into the next one.

* "the Microsoft Access engine (ACE) is not available"
  Nothing was changed. Install "Microsoft Access Database Engine 2010
  Redistributable". The bitness must match the .bat you ran - for the
  32-bit .bat install AccessDatabaseEngine.exe, the one WITHOUT _X64.

* "still held open by some program"
  Nothing was changed. Close Clarity/Access on this PC and run again.

* "these tables were not found in primary or secondary"
  Nothing was changed. A wrong or partial database file was copied down.

* "schemas differ for: ..."
  Stage 2 refused to write because secondary's columns do not match
  primary's. Primary is untouched and fine. Send me the log.

* Interrupted (reboot, window closed)
  Just run it again. It resumes and never duplicates anything.


ONE THING TO KNOW
-----------------
Clarity numbers new sales slips as "highest existing + 1". The first GP
import put rows high in that range, so your live slips have been numbering
from 900,002 upward since 22 Aug. That is cosmetic - nothing collides, and
the slip NUMBER your staff and customers see (150,374, 150,375, ...) is a
separate sequence that is unaffected. No action needed.
